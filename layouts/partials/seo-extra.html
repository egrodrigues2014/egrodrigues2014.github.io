{{/* Head additions the theme does not provide. Written from scratch, so it carries no THEME-VERSION marker — nothing here is copied from the theme. Called from this project's copy of layouts/partials/opengraph.html, which is the cheapest seam available: Toha has no head.html, no custom-head hook and no hooks/ directory, and it emits from two independent standalone templates — layouts/index.html (the home page, which does NOT use baseof) and layouts/_default/baseof.html. opengraph.html is 19 lines and is called by both, so owning it covers every page at a third of the surface of owning the two templates. 1. hreflang. Toha v4.16.0 emits none at all — verified, zero occurrences in all three languages — while getting right. For a trilingual site that is a real SEO gap: without it a search engine treats the three versions as unrelated pages, or as duplicates. Built from .AllTranslations, which lists only versions that actually exist and includes the current page, so the set is reciprocal as the spec requires. The value uses the same expression as in baseof (.Language.Locale falling back to .Language.Lang) so the two can never disagree: en, es-ES, pt-BR. Skipped entirely on pages with a single version — a blog post with no translation gets nothing, which is correct. 2. Pre-launch noindex. Paired with layouts/robots.txt and driven by the single switch params.prelaunch, so launching is a one-line change rather than a hunt for references. Both are needed: robots.txt stops crawling, but a URL discovered another way can still be listed; this meta is what actually prevents indexing. 3. og:image dimensions and alt. The theme emits og:image and nothing else about it. Without width and height a consumer has to fetch and measure the file before it can decide on a layout, and several skip the large card rather than wait. Stating them lets LinkedIn commit to the 1.91:1 card immediately. 4. twitter:* on the home page. The theme calls twitter_cards.html only from baseof.html, and the home page renders through layouts/index.html, which does not use baseof — so the home, the one page with three language versions, had no twitter card at all. Verified: zero twitter: matches in public/index.html, while every other page got Hugo's embedded template with card=summary. Emitted here only for .IsHome, so the embedded template still owns every other page and nothing is duplicated. Elsewhere only twitter:image is added, which the embedded template omits when a page has no image resource. */}} {{- /* x-default is identified by an empty .Site.LanguagePrefix, which is true only for the default content language — the one served at the site root. There is no site.DefaultContentLanguage in Hugo's API (tried it; the build fails with "can't evaluate field DefaultContentLanguage"), and hardcoding "en" here would silently diverge the day hugo.yaml changes. Note this depends on defaultContentLanguageInSubdir staying false, which is our configuration. */ -}} {{- if gt (len .AllTranslations) 1 }} {{- range .AllTranslations }} {{- end }} {{- range .AllTranslations }} {{- if not .Site.LanguagePrefix }} {{- end }} {{- end }} {{- end }} {{- if site.Params.prelaunch }} {{- end }} {{- /* The card image and its dimensions. Resolved the same way the theme's opengraph.html resolves og:image, so the two can never point at different files: page images first, then site.openGraph.image, then the author photo. The dimensions are hardcoded because they are a property of the generator, not of the data: scripts/make-og-card.mjs asserts the PNG it writes is exactly 1200x630 and fails otherwise. Reading them from the file would mean an image pipeline for a value that is fixed by contract. */ -}} {{- $og := (index hugo.Data site.Language.Lang).site.openGraph -}} {{- $img := "" -}} {{- with .Params.images }}{{ $img = index . 0 }}{{ else }} {{- $img = $og.image | default (index hugo.Data site.Language.Lang).author.image -}} {{- end }} {{- with $img }} {{- end }} {{- if .IsHome }} {{- with $img }} {{- end }} {{- else }} {{- with $img }} {{- end }} {{- end }}
